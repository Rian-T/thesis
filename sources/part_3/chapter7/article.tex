\section{The Lymphoma eCRF}

The previous chapter trained MC-bio-gliner as a generalist extractor. We now
adapt it to fill an eCRF from all reports written about one patient. We use
lymphoma as the case study.

We use the synthetic lymphoma study constructed in \Cref{chap:synthetic}. Its
eCRF contains 89 fields defined for the lymphoma use case of the OncoLab
programme. These fields are grouped into ten sections, including disease
history, two treatment lines, imaging, and patient status.
\Cref{fig:p3-task} illustrates the task.

\input{sources/part_3/figures/fig01_longitudinal_to_ecrf}

The full form is larger than this two-field example. \Cref{fig:p3-form-preview}
shows a small extract from three of its sections.

\input{sources/part_3/figures/fig01_form_preview}

The synthetic corpus contains 1,540 training records, 100 validation records,
and 410 test records.

We compare extractive and generative systems. Extractive systems score each
text span against each field. Generative systems return all 89 fields in one
structured output.

\section{Evaluation Protocol}

For each patient and field, the eCRF keeps one value. If a model returns several
values, we retain the one with the highest confidence.

We report three metrics. Span-$F_1$ checks whether the predicted evidence span
overlaps the reference evidence span. Value-$F_1$ compares the normalized tokens
of the predicted and reference values. A prediction is correct when their
Jaccard similarity is at least 0.5. This threshold allows differences in
formatting between extracted spans and generated values. Exact match requires
both the value and its evidence span to be correct. These metrics compare text
and do not measure clinical equivalence.

Extractive models assign a confidence to each prediction. We select one
threshold per model on the 100 validation records and apply it to the 410 test
records. Generative models return one value per field and do not require a
threshold. We compute paired confidence intervals over the test records.

\section{Results on the Lymphoma eCRF}

\subsection{Raw Model Outputs}

We compare three approaches to filling the form. The first treats each eCRF
field as an extractive question-answering task and returns one answer span from
the record. The second uses open-vocabulary extraction. We compare MC-bio-gliner
with GLiNER-BioMed~\citep{zaratiana2025glinerbiomed}. The third prompts four
Qwen3.5 decoder models to
return the complete form as structured JSON. These systems have different
training objectives and output formats, so this is not a controlled scaling
experiment. The silver eCRF was produced by Qwen3-235B in
\Cref{chap:synthetic}. Similar conventions between this model and the Qwen3.5
generators may favour the generators. The scores therefore measure agreement
with a generated reference rather than clinical accuracy.

Qwen3.5-4B obtains the highest value-$F_1$ at 0.672. Qwen3.5-9B reaches 0.665,
so increasing the model size does not appear to improve the score further. The
released 150-million-parameter MC-bio-gliner reaches 0.634. Its gap to
Qwen3.5-4B is 0.038, with 27 times fewer parameters.

\subsection{Field Competition}

After selecting one value per field, the same evidence span may still be
assigned to several fields because each field is scored independently. Field
competition compares assignments whose evidence spans have an intersection
over union above 0.5 and keeps only the most confident one. This prevents one
passage from filling several fields, but it cannot correct a medically
incorrect prediction.

Field competition improves all six extractive systems. For the published
MC-bio-gliner, value-$F_1$ rises from 0.634 to 0.640. Field competition is a
post-processing rule for extractive models, which predict each field
independently. Generative models already return a joint answer and do not
require this correction. We nevertheless apply the same rule to all systems in
the final comparison and also report their raw scores. For Qwen3.5-9B, the rule
removes some correct values and reduces value-$F_1$ from 0.665 to 0.650, a
paired change of $-0.0153$ (95\% CI $[-0.0176, -0.0129]$), as shown in
\Cref{fig:p3-decoding-competition}.

After field competition, the released MC-bio-gliner reaches 0.640

during adaptation helps the extractor. The resulting variant reaches 0.657
after field competition. Its paired difference from Qwen3.5-4B is $-0.0005$

\section{Beyond the Aggregate Score}

Value-$F_1$ does not distinguish a wrong value from a correct value assigned to
the wrong field. Among their errors, wrong-field assignments account for 48.9\%
for MC-bio-gliner and 38.8\% for Qwen3.5-4B. MC-bio-gliner therefore makes more
role confusions, where the correct string is placed in the wrong part of the
form.

We also measure how well each model ranks its predictions by confidence. This
analysis includes all predictions, including those below the threshold used for
value-$F_1$. Qwen3.5-4B obtains a lower risk--coverage area, at 0.207 compared
with 0.239, and a higher precision at 50\% coverage, at 0.828 compared with
0.770. MC-bio-gliner fills more fields, but its confidence scores separate
correct and incorrect predictions less accurately
(\Cref{fig:p3-risk-coverage}).

MC-bio-gliner has 150 million parameters. In bfloat16, its weights require about
0.3 GB, compared with roughly 8 GB for Qwen3.5-4B and 18 GB for Qwen3.5-9B.
These estimates exclude activations and runtime overhead. The smaller model is
easier to fit on hospital hardware, but it is not faster per record because it
must query all 89 field descriptions.

The biomedical question-answering encoder reaches 0.417 value-$F_1$, below the
open-vocabulary extractors. This could be explained by its weaker training
signal. Its SQuAD-style head uses one answer span per field and record, while
GLiNER learns from all annotated mentions.

\section{Generalization and Transfer}

We first measure how much generated supervision the extractor needs. We train
MC-bio-gliner with 10, 50, 100, 500, or 1,540 synthetic records. Value-$F_1$
increases from 0.182 with 10 records to 0.485 with 50 and 0.659 with all 1,540
records (\Cref{fig:p3-data-efficiency}). Fifty records already provide 74\% of
the final score, although performance continues to improve with more data.

and FRACCO contain human-written text with human NER annotations. They do not

unstable. FRACCO contains three ICD-O types and about 34 annotated mentions per

appears on the longitudinal form-filling task for which it was adapted.

\section*{Conclusion}

We release MC-bio-gliner, a 150-million-parameter French biomedical extractor
trained without hospital records. On the synthetic lymphoma eCRF, it reaches
0.640 value-$F_1$, within 0.018 of Qwen3.5-4B with 27 times fewer parameters.
Its weights require about 0.3 GB in bfloat16, compared with 8 GB for the
generator. When adapted with only 50 synthetic training records, it also
recovers 74\% of the score obtained with all 1,540 records.

The model provides a reusable starting point for new clinical forms. It can be
trained and shared using only public and generated text. A hospital could then
adapt it on site with field descriptions and a small set of annotated records,
without sending patient data to an external service. The complete task must now
be evaluated on real hospital records with human annotations.
